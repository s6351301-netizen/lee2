系統架構
1.所有資料表都會由"members"與"account"連結出來的表格,依照需求寫入個種類型資料表內.
2.登入時,要把帳號(MAIL當帳號)在"members"對應的"name姓名"和"new_member現在會員編號"鎖對應的ID傳到登入後的網頁.
3.每一個已登入後的網頁,有需要的會直接顯示出"name姓名"和"new_member現在會員編號"值.
甚至會用"members"的number_of_houses房數emperor_shizu世祖(台灣算起)generation世代(大甲算起)去真實核對人物,
避免同一房同一代甚至連姓名都一樣的人,只差new_member現在會員編號不一樣,被錯誤的導入系統寫入資料庫.
4.使用"預存程序"名稱"sync_account_members"類型"PROCEDURE"去讓PHP網頁做會員資料編輯後,同時將"members"與"account"關聯的欄位全部一致性.
5.等待全部功能完成後,寫"觸發器"名稱"trigger_account_members"讓所有資料表從"members"與"account"所引用而寫入各資料表的會員資料做資料同部,
避免有各資料部一致性產生.
6.為避免以後在寫各種功能時,還會再新增"members"與"account"資料表的欄位.不直接引用這兩個資料表,
而是採用account_members_view檢視表去做API連接資料庫的連結.
只要未來此2個資料表欄位更動時,重新再拉一次account_members_view檢視表即可.

以下提供登入網頁,與已經完成許願卡的原始碼.
提供在登入後,寫出各網頁共同都要使用要被被引用的API的PHP網頁.

DELIMITER $$
--
-- 程序
--
CREATE DEFINER=`root`@`localhost` PROCEDURE `sync_account_members` (IN `p_id` INT, IN `p_name` VARCHAR(50), IN `p_new_member` VARCHAR(50), IN `p_status` VARCHAR(20))   BEGIN
    -- 安全機制：發生任何 SQL 錯誤就整筆取消（Rollback），保證資料不會改一半
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        ROLLBACK;
    END;

    -- 開始事務
    START TRANSACTION;

    -- 更新 account 表 (status 欄位是 varchar)
    UPDATE account
    SET name = p_name,
        new_member = p_new_member,
        status = p_status,
        updated_at = NOW()
    WHERE id = p_id;

    -- 更新 members 表 (status 欄位是 tinyint，MySQL 會自動轉換)
    UPDATE members
    SET name = p_name,
        new_member = p_new_member,
        status = CAST(p_status AS SIGNED),
        update_time = NOW()
    WHERE id = p_id;

    -- 確認無誤，提交存檔
    COMMIT;
END$$

DELIMITER ;

  `password` varchar(255) NOT NULL COMMENT '密碼',
  `role` enum('admin','user','clan') DEFAULT 'user' COMMENT '權限(管理者/派下員/宗親)',
  `join_date` timestamp NOT NULL DEFAULT current_timestamp() COMMENT '註冊日期',
  `status` varchar(20) DEFAULT '1' COMMENT '帳號停用或使用中(1:使用中, 0:停用)',

  `remarks` varchar(255) DEFAULT NULL COMMENT '備註',
